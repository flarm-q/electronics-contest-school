# K210 视觉巡线技术方案

## 1. 目标

当前工程改用 K210 作为视觉巡线模块，负责图像采集、黑线提取、偏差计算、方向趋势判断和丢线识别，并通过串口把结果发送给 STM32。STM32 侧只接收结构化视觉结果，不再参与图像处理。

赛道地图为白底黑线，黑线宽度约 1.8 cm。后续 K210 还可以继续扩展红、绿、蓝色块识别，但当前阶段先把基础巡线跑稳，色块只保留接口，不介入巡线控制。

> 说明：工程里部分旧变量名和函数名可能仍保留 `K230_` 前缀，这是历史命名，文档这里统一按 K210 方案描述，代码重命名后续再整理。

## 2. 总体架构

```text
摄像头图像
  -> K210 图像处理
  -> 黑线中心 / 方向 / 可信度 / 丢线状态
  -> UART 发送巡线帧
  -> STM32 串口接收与解析
  -> 视觉巡线控制
  -> 左右电机差速转向
```

分工原则：

- K210：完成黑线识别、主线选择、干扰过滤、色块识别。
- STM32：不做图像判断，只处理 K210 发来的巡线帧。
- 旧八路传感器巡线：不再作为新方案基础，只保留回退入口。
- 电机、编码器、MPU6050、平衡控制、速度控制继续保留。

## 3. 地图分析

地图主体是白底黑线的外侧大闭环，底部中间有内圆，左侧中部有短横线，右侧竖直段附近有红、蓝、绿标记。

巡线目标是外侧大闭环，不是底部内圆，也不是左侧短横线。

主要难点：

- 内圆和外圈底边可能同时入镜，容易把黑线中心拉偏。
- 圆角区域需要提前转向，不能只看最靠近车头的窄 ROI。
- 左侧短横线是干扰线，不能被当成主线。
- 右侧色块后续用于事件识别，当前阶段不参与巡线控制。

## 4. K210 端视觉巡线逻辑

### 4.1 不复用旧传感器巡线逻辑

旧八路巡线通常依赖离散状态表，例如左偏、右偏、十字、丢线。K210 视觉巡线不走这条路，而是直接计算连续误差：

```text
error = line_center_x - image_center_x
```

含义：

- `error < 0`：黑线在画面左侧，车辆需要向左修正。
- `error > 0`：黑线在画面右侧，车辆需要向右修正。
- `error = 0`：黑线中心接近画面中心。

巡线控制应基于连续误差、方向趋势和可信度，而不是八路传感器的离散组合。

### 4.2 图像采集

K210 端建议保持固定分辨率和稳定帧率，优先保证前方赛道区域清晰。巡线阶段以黑白分割为主，不需要复杂识别流程。

采集建议：

- 只保留前方有效视野，不必全图参与计算。
- 亮度变化大时，优先先调阈值，不要先改控制参数。
- 显示窗口只用于调试，不参与控制。

### 4.3 黑线提取

白底黑线场景建议用亮度阈值或灰度二值化：

```text
低亮度区域 -> 黑线
高亮度区域 -> 背景
```

基础策略：

- 先用固定阈值跑通。
- 如果现场光照变化明显，再改动态阈值或自适应阈值。
- 面积太小、形状太碎、与线宽明显不符的区域不作为主线。

### 4.4 ROI 设计

不建议整图直接求黑色重心。更稳妥的做法是设置多个横向 ROI：

```text
far_roi     远处 ROI，用于提前发现弯道
middle_roi  中处 ROI，用于判断路线趋势
near_roi    近处 ROI，用于当前转向误差
```

融合方式可以按近大远小分权：

```text
error = near_error * 0.5 + middle_error * 0.3 + far_error * 0.2
```

近处权重大，保证当前不偏线；中远处用于提前入弯。

### 4.5 主线选择

同一 ROI 内可能出现多个黑色候选区域，尤其是在内圆附近。因此不能简单取面积最大值，而要按主线连续性选择：

- 优先选择与上一帧位置连续的区域。
- 优先选择沿车辆前进方向延伸的区域。
- 忽略面积过小、宽高比异常、与线宽明显不符的区域。
- 多个候选同时存在时，选择和上一帧误差、趋势最一致的那个。
- 如果当前帧可信度低，就不要硬输出一个随机偏差。

### 4.6 方向角与可信度

除 `error` 外，K210 还应输出一个路线方向量 `angle`，用于提前处理圆角和弯道。

可以由近、中、远三个 ROI 的中心差值估算：

```text
angle = far_center_x - near_center_x
```

含义：

- `angle < 0`：路线向左发展。
- `angle > 0`：路线向右发展。
- `angle` 绝对值越大，弯道趋势越明显。

可信度 `confidence` 可由以下因素综合决定：

- ROI 内是否检测到黑线。
- 黑线面积是否合理。
- 黑线宽度是否接近预期。
- 多个 ROI 的中心点是否连续。
- 当前帧与上一帧变化是否正常。

建议输出范围：`0~100`。

## 5. 串口协议

当前巡线建议使用独立帧：

```text
$L,error,angle,confidence,flags#
```

示例：

```text
$L,-23,5,86,1#
```

字段说明：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `error` | `int16_t` | 黑线中心相对画面中心的偏差，左负右正 |
| `angle` | `int16_t` | 路线趋势，左负右正 |
| `confidence` | `uint8_t` | 可信度，范围 0~100 |
| `flags` | `uint8_t` | 状态标志位 |

`flags` 建议定义：

| bit | 含义 |
| --- | --- |
| bit0 | `valid`，当前巡线结果有效 |
| bit1 | `lost`，当前丢线 |
| bit2 | `curve`，检测到明显弯道 |
| bit3 | `marker`，检测到色块或特殊标记 |

后续色块识别继续保留：

```text
$C,color_id,pos,size#
```

其中 `color_id` 可按红、绿、蓝和空目标区分。

## 6. K210 端脚本改造建议

K210 端建议独立放在 `HARDWARE/K210/` 下，主流程只做视觉和串口输出，不把控制逻辑塞进识别流程里。

建议保留的功能块：

```text
find_line()
send_line()
update_line_history()
```

建议的数据结构：

```text
line = {
    error,
    angle,
    confidence,
    flags
}
```

主循环建议流程：

1. 获取图像
2. 识别黑线并计算 `line`
3. 发送 `$L` 巡线帧
4. 可选：显示调试图像
5. 色块识别先保留为调试信息，不参与控制

第一阶段不建议让色块改变巡线结果。基础巡线稳定后，再把色块事件接到 STM32 状态机。

## 7. STM32 端接入方案

### 7.1 串口接入

K210 视觉帧建议走 `USART3`，对应 STM32 的 `PB10/PB11`。如果当前蓝牙还占着这个口，需要先统一串口分配，方案默认 K210 独占 `USART3`。

### 7.2 新增视觉巡线模块

建议单独增加视觉巡线模块，不和旧八路传感器模块混用：

```text
HARDWARE/VISION/
  vision_track.c
  vision_track.h
```

模块职责：

- 接收 UART 数据。
- 解析 `$L` 巡线帧。
- 保存最新视觉巡线状态。
- 提供 `error`、`angle`、`confidence`、`valid` 给控制层。
- 判断通信超时和丢线。

建议状态结构：

```text
error
angle
confidence
flags
valid
lost
last_update_ms
```

### 7.3 控制逻辑

STM32 不再复用旧八路巡线判断表，直接使用视觉连续误差：

```text
turn_output = Kp * error + Kd * angle
```

然后叠加到左右电机：

```text
left_motor  = balance_output + speed_output - turn_output
right_motor = balance_output + speed_output + turn_output
```

方向如果反了，先改误差符号或转向符号，不要先盲目加大参数。

### 7.4 丢线和通信异常

必须加保护：

- 超过 100~200 ms 没收到有效 `$L` 帧，视为通信超时。
- `valid = 0` 或 `confidence` 太低，视为当前结果不可靠。
- 丢线后不要长期沿用旧误差。

建议处理方式：

- 短时间丢线：降速，短暂保持上一方向。
- 持续丢线：停止前进，只保持平衡。
- 恢复识别：平滑恢复巡线控制。

## 8. 旧八路传感器代码关闭边界

旧巡线代码先不删除，只注释或用宏关闭。建议关闭内容：

- `USER/main.c` 中旧巡线初始化调用。
- 主循环或定时任务中的旧巡线处理函数。
- 专用于八路传感器的 GPIO 采集逻辑。
- 旧巡线控制输出对电机转向的影响。

保留内容：

- 原 `HARDWARE/TRACKING/` 文件。
- 电机、编码器、平衡控制相关公共代码。
- 串口、OLED、调试输出等基础功能。

建议使用编译宏区分：

```text
ENABLE_SENSOR_TRACKING = 0
ENABLE_K210_LINE_TRACKING = 1
```

这样后续需要回退或对比测试时，可以快速切换。

## 9. 后续色块避障扩展

基础巡线稳定后，再加入色块避障。K210 可以继续输出 `$C,color_id,pos,size#`，STM32 根据视觉事件切换状态机。

建议后续流程：

```text
K210 同时输出 $L 巡线帧和 $C 色块帧
STM32 平时根据 $L 巡线
检测到有效 $C 色块事件后进入避障状态机
避障动作完成后恢复视觉巡线
```

避障不建议直接写在 K210 巡线算法里。K210 只负责报告视觉结果，STM32 根据车体状态、电机控制和当前任务阶段决定如何响应。

## 10. 推荐实施步骤

1. 在 STM32 中关闭旧八路传感器巡线调用，不删除代码。
2. 在 K210 端新增 `find_line()` 和 `$L` 巡线帧发送。
3. STM32 新增视觉巡线串口解析模块。
4. 先用固定 `$L` 测试数据验证 STM32 解析正确。
5. 再接入真实图像处理，观察 `error`、`angle`、`confidence` 是否稳定。
6. 将视觉 `error` 和 `angle` 接入转向控制。
7. 低速实车调试 `Kp`、`Kd` 和速度。
8. 增加丢线保护。
9. 基础巡线稳定后，再加入色块避障状态机。

## 11. 当前阶段结论

当前阶段应把 K210 作为新的视觉巡线传感器，重写一套基于图像连续误差的巡线逻辑。旧八路传感器巡线代码只保留作为历史参考和回退方案，不参与新视觉巡线控制。

第一阶段目标是让车辆在白底黑线地图上稳定跟随外侧大闭环，并正确过滤底部内圆、左侧短横线和色块干扰。等基础巡线稳定后，再把已有色块识别能力扩展为避障功能。
