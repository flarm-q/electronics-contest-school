# K210视觉巡线调参说明

## 1. 适用范围

这份说明对应当前工程的 K210 视觉方案，包含两部分功能：

1. 视觉巡线
2. 颜色识别避障

当前控制链路已经切换为 K210 + STM32 协同方式，旧的 K230 巡线和八路传感器巡线不再作为主流程使用。

---

## 2. 当前数据流

```text
K210 摄像头
  -> 图像采集
  -> 黑线识别 / 色块识别
  -> 串口发送 $L 或 $C 帧
  -> STM32 USART3 接收
  -> 控制层选择“避障 / 巡线 / 保持平衡”
  -> 电机输出
```

串口约定：

- K210 使用 `UART1`
- STM32 使用 `USART3`
- 波特率：`115200`

K210 发送帧格式：

```text
$L,error,angle,confidence,flags#
$C,color_id,pos,size#
```

---

## 3. K210 端先调什么

### 3.1 图像方向

当前脚本里已经固定为：

```python
IMAGE_HMIRROR = 1
IMAGE_VFLIP = 1
```

如果你看到屏幕图像是反的，优先改这里，不要先动阈值和控制参数。

- 左右反了：改 `IMAGE_HMIRROR`
- 上下反了：改 `IMAGE_VFLIP`
- 两个都不对：两个都改

### 3.2 图像尺寸

当前使用：

```python
FRAME_WIDTH = 320
FRAME_HEIGHT = 240
```

这套参数配合当前 ROI 和串口协议已经固定好。除非你要重写整套视觉逻辑，否则不建议随意改分辨率。

---

## 4. 巡线 ROI 参数

当前脚本里 `far` 已经注释掉，实际在用的是 2 个 ROI：

```python
mid  : (50, 125, 220, 40)   权重 0.5
near : (50, 175, 220, 50)   权重 0.6
```

含义：

- `mid`：看中间区域，辅助判断趋势
- `near`：看近处，负责当前修正

如果后面想恢复远处预判，可以把 `far` 那行取消注释再试。

调参规则：

1. `near` 权重大，车头修正更灵敏
2. `mid` 负责补趋势，避免只看近处导致反应迟
3. ROI 太高：容易看到不该看的路段
4. ROI 太低：容易反应慢，转弯跟不上

如果车子“转弯晚、容易甩出去”，先适当提高 `mid` 的作用；
如果车子“来回抖、一直找线”，先降低 `mid` 的影响，保留 `near` 主导。

---

## 5. 黑线阈值怎么调

当前黑线阈值：

```python
BLACK_THRESHOLD = (0, 45, -20, 20, -20, 20)
```

这是一组 LAB 阈值，用来提取黑色区域。

调法很直接：

- 黑线识别不到：先放宽阈值
- 背景误识别太多：再收紧阈值
- 光线偏暗：适当提高 L 上限范围
- 地面反光严重：优先调阈值，不要先改 PD

经验顺序：

1. 先保证黑线能稳定被提取出来
2. 再保证提取出来的是“线”，不是大块噪声
3. 最后再调控制参数

---

## 6. blob 过滤参数

当前过滤值：

```python
MIN_PIXELS = 120
MIN_AREA = 120
MIN_COLOR_PIXELS = 200
MIN_COLOR_AREA = 200
```

作用：

- `MIN_PIXELS` / `MIN_AREA`：过滤巡线黑块
- `MIN_COLOR_PIXELS` / `MIN_COLOR_AREA`：过滤颜色块

怎么调：

- 误检太多：调大
- 线太细、经常识别不到：调小

注意别一次改太猛。建议每次按 20% 左右幅度微调。

## 7. 巡线输出参数

当前 K210 巡线输出的核心字段：

- `error`：线中心相对画面中心的偏差，左负右正
- `angle`：路线趋势，左负右正
- `confidence`：可信度，0 到 100
- `flags`：状态位

当前脚本的 flags 含义：

- bit0：有效
- bit1：丢线
- bit2：弯道
- bit3：标记位

### 7.1 什么时候算丢线

当前逻辑里，如果没有找到有效黑线，就会发丢线状态。

此时 STM32 会：

- 停止继续前进
- 保持平衡
- 等待视觉恢复

### 7.2 可信度怎么用

当前控制层用到的门限：

```c
#define K210_LINE_MIN_CONFIDENCE 35
```

意思是：

- 低于 35：不认为这帧巡线足够可靠
- 高于 35：才允许进入巡线控制

如果现场光照不稳定、线边缘发虚，可以先把这个值略降一点；
如果误检很多，可以把它提高。

## 8. 巡线控制参数

当前 STM32 侧巡线参数：

```c
#define K210_LINE_BASE_SPEED -10
#define K210_LINE_MIN_CONFIDENCE 35
#define K210_LINE_TURN_LIMIT 100
#define K210_LINE_ERROR_KP 0.32f
#define K210_LINE_ANGLE_KD 0.18f
```

控制关系：

```text
turn = error * K210_LINE_ERROR_KP + angle * K210_LINE_ANGLE_KD
```

### 8.1 `K210_LINE_BASE_SPEED`

这是巡线时的基础前进速度。

- 数值更大：前进更快
- 数值更小：前进更稳
- 负号方向要和当前电机安装方向保持一致

如果车子巡线时总是冲得太快，先把它往 0 方向调一点。

### 8.2 `K210_LINE_ERROR_KP`

这是横向偏差的主修正。

- 太小：回线慢，容易压线
- 太大：左右来回抖，像“甩方向”

### 8.3 `K210_LINE_ANGLE_KD`

这是趋势项，负责提前处理弯道。

- 太小：入弯晚
- 太大：直线段也会被提前拉偏

### 8.4 `K210_LINE_TURN_LIMIT`

转向最大限幅。

- 太小：转不过急弯
- 太大：转向过猛，车体不稳

## 9. 颜色识别避障参数

当前避障参数：

```c
#define K210_AVOID_BASE_SPEED 8
#define K210_AVOID_TURN_STRONG 45
#define K210_AVOID_TURN_MID 30
#define K210_AVOID_MIN_SIZE 200
```

### 9.1 触发条件

STM32 侧当前只在以下条件满足时才认为颜色避障有效：

- `color_id` 为红、绿、蓝之一
- `size >= K210_AVOID_MIN_SIZE`

### 9.2 参数作用

- `K210_AVOID_BASE_SPEED`：避障时的前进速度
- `K210_AVOID_TURN_STRONG`：色块在左/右两侧时的强转向量
- `K210_AVOID_TURN_MID`：色块居中时的中等转向量
- `K210_AVOID_MIN_SIZE`：最小有效面积，防止小噪点误触发

调参建议：

- 误触发多：提高 `K210_AVOID_MIN_SIZE`
- 绕障不够果断：提高 `K210_AVOID_TURN_STRONG`
- 转向太猛：降低 `K210_AVOID_TURN_STRONG`

## 10. 平衡相关参数

K210 只是上层视觉输入，最终还是要靠平衡车本体参数稳住。

当前核心参数：

```c
float Vertical_Kp = -500;
float Vertical_Kd = -1.92f;
float Velocity_Kp = -0.44f;
float Velocity_Ki = -0.0022f;
float Turn_Kd = 0.6f;
float Turn_Kp = 20;
```

调参顺序建议：

1. 先调 `Vertical_Kp` / `Vertical_Kd`
2. 再调 `Velocity_Kp` / `Velocity_Ki`
3. 最后再看 `Turn_Kp` / `Turn_Kd`

原因很简单：

- 车都站不稳，视觉调得再好也没用
- 先把直立调稳，再让速度环跟上
- 最后才是转向和巡线

---

## 11. 推荐调参顺序

### 第一步：看画面

确认：

- 画面方向正确
- 线在画面里能稳定识别
- 色块不会乱跳

### 第二步：调黑线阈值

目标：

- 黑线能被稳定分割出来
- 背景误检尽量少

### 第三步：调 ROI

目标：

- 近处能稳住
- 远处能提前看弯

### 第四步：调巡线控制

先调：

- `K210_LINE_ERROR_KP`

再调：

- `K210_LINE_ANGLE_KD`

最后看：

- `K210_LINE_TURN_LIMIT`
- `K210_LINE_BASE_SPEED`

### 第五步：调颜色避障

最后再调：

- `K210_AVOID_MIN_SIZE`
- `K210_AVOID_TURN_STRONG`
- `K210_AVOID_TURN_MID`

## 12. 串口和调试输出

STM32 主循环当前会输出：

```text
Pitch
Roll
Yaw
VisionError
VisionAngle
VisionConfidence
VisionFlags
EncoderLeft
EncoderRight
SpeedDisplay
```

你现场调参时重点看这几个量：

- `VisionError`：横向偏差
- `VisionAngle`：弯道趋势
- `VisionConfidence`：当前视觉可信度
- `VisionFlags`：当前是否有效、是否丢线

如果 `VisionError` 在来回跳，但画面里黑线其实很稳，说明阈值或 ROI 可能有问题；
如果 `VisionError` 很平稳，但车一直偏，说明 STM32 侧控制参数要调。

## 13. 常见问题

### 13.1 画面反了

先改：

```python
IMAGE_HMIRROR
IMAGE_VFLIP
```

### 13.2 黑线识别不到

优先检查：

1. 光照
2. `BLACK_THRESHOLD`
3. `MIN_PIXELS`
4. ROI 位置

### 13.3 一直误识别

优先检查：

1. `BLACK_THRESHOLD` 是否过宽
2. ROI 是否扫到了背景黑块
3. `MIN_PIXELS` 是否太小

### 13.4 车子来回抖

优先检查：

1. `K210_LINE_ERROR_KP` 是否过大
2. `K210_LINE_ANGLE_KD` 是否过大
3. `K210_LINE_BASE_SPEED` 是否过高

### 13.5 入弯太晚

优先检查：

1. `mid` ROI 是否太弱
2. `K210_LINE_ANGLE_KD` 是否太小
3. `K210_LINE_TURN_LIMIT` 是否太小
