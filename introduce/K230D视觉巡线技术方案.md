# K230D 视觉巡线技术方案

## 1. 目标

当前工程不再使用原八路传感器巡线逻辑，改为使用 K230D 完成视觉巡线。地图为白底黑线，黑线宽度约 1.8 cm。K230D 负责图像采集、黑线识别、偏差计算和状态判断，并通过串口把结果发送给 STM32。STM32 只接收视觉巡线结果，并根据视觉偏差完成转向控制。

后续 K230D 还需要识别红、绿、蓝色块，并配合 STM32 实现避障功能。但当前第一阶段只完成基础视觉巡线，色块识别代码可以保留，不参与巡线控制。

## 2. 总体架构

```text
摄像头图像
  -> K230D 图像处理
  -> 黑线中心 / 方向 / 可信度 / 丢线状态
  -> UART 发送巡线帧
  -> STM32 串口接收与解析
  -> 视觉巡线控制
  -> 左右电机差速转向
```

分工原则：

- K230D：完成所有视觉判断，包括黑线提取、主线选择、干扰过滤、色块识别。
- STM32：不参与图像处理，只处理 K230D 发来的结构化结果。
- 原八路传感器巡线逻辑：不再作为视觉巡线的基础，不复用其位置判断和转向决策。
- 电机、编码器、MPU6050、平衡控制、速度控制等基础模块继续保留。

## 3. 地图分析

地图主要由一个大圆角矩形闭环组成，白底黑线。底部中间有一个内圆，左侧中部有一段短横线，右侧竖直段有红、蓝、绿三个色块标记。

需要跟随的主路线是外侧大闭环，不是底部内圆，也不是左侧短横线。

主要难点：

- 底部内圆可能与外圈底边同时进入摄像头视野，导致黑线中心被拉偏。
- 圆角区域需要提前转向，只看近处 ROI 容易入弯滞后。
- 左侧短横线是干扰线，不能被识别为主线。
- 右侧红、蓝、绿色块后续用于避障或位置事件，当前阶段不参与巡线控制。

## 4. K230D 端视觉巡线逻辑

### 4.1 不复用旧传感器巡线逻辑

原八路传感器巡线通常基于 8 个数字量或模拟量状态组合判断，例如左偏、右偏、十字、丢线等。视觉巡线不采用这种状态表方式，而是直接从图像中计算连续误差：

```text
error = line_center_x - image_center_x
```

其中：

- `error < 0`：黑线在画面左侧，车辆需要向左修正。
- `error > 0`：黑线在画面右侧，车辆需要向右修正。
- `error = 0`：黑线中心与画面中心基本一致。

转向控制应基于连续误差、方向角和可信度，而不是八路传感器的离散状态。

### 4.2 图像采集

当前 `HARDWARE/K230/color_ecognition.py` 已经包含摄像头、显示和 UART1 初始化框架：

- 摄像头：`Sensor.VGA`
- 图像格式：`RGB565`
- 串口：UART1，115200
- 引脚：GPIO40 为 UART1_TXD，GPIO41 为 UART1_RXD

第一阶段可以继续沿用这个框架，在现有脚本中新增视觉巡线函数。

### 4.3 黑线提取

地图为白底黑线，建议在 K230D 上完成灰度或亮度阈值分割：

```text
亮度低于阈值 -> 黑线
亮度高于阈值 -> 白色背景
```

基础方案：

- 使用固定阈值提取黑线。
- 根据现场光照调整阈值。
- 如果光照变化明显，再改为自适应阈值或动态阈值。

为了避免色块误判为黑线，后续可以增加过滤条件：

- 黑线应为低亮度、长条形、连续区域。
- 色块通常面积较小，颜色特征明显，可单独用 LAB 阈值识别。
- 小面积深色噪声不参与主线选择。

### 4.4 ROI 设计

不建议整图直接求黑色重心。应在画面前方设置多个横向 ROI：

```text
far_roi     远处 ROI，用于提前发现圆角和弯道
middle_roi  中处 ROI，用于判断路线趋势
near_roi    近处 ROI，用于当前转向误差
```

融合方式：

```text
error = near_error * 0.5 + middle_error * 0.3 + far_error * 0.2
```

近处权重大，保证当前不偏线；中远处权重用于提前入弯。

### 4.5 主线选择

每个 ROI 内可能出现多个黑色区域，尤其是在底部内圆附近。因此不能简单选择最大黑色区域，应使用主线选择规则：

- 优先选择与上一帧主线位置连续的黑色区域。
- 优先选择靠近车辆前进方向延伸的黑色区域。
- 忽略面积过小、宽高比异常、与 1.8 cm 线宽不匹配的区域。
- 当同一 ROI 有多个候选区域时，选择与上一帧 `error` 和 `angle` 最一致的区域。
- 如果候选区域可信度低，标记 `valid = 0`，不要输出随机偏差。

### 4.6 方向角与可信度

除了 `error`，K230D 还应计算一个路线方向量 `angle`。它可以由近、中、远三个 ROI 的中心点拟合得到：

```text
angle = middle_center_x - near_center_x
```

或者：

```text
angle = far_center_x - near_center_x
```

含义：

- `angle < 0`：路线向左发展。
- `angle > 0`：路线向右发展。
- `angle` 绝对值越大，弯道趋势越明显。

可信度 `confidence` 可以根据以下因素计算：

- ROI 中是否检测到黑线。
- 黑线面积是否在合理范围。
- 黑线宽度是否接近预期。
- 多个 ROI 的中心点是否连续。
- 当前帧与上一帧变化是否合理。

建议输出范围为 `0~100`。

## 5. K230D 串口协议

现有色块识别脚本使用字符串协议：

```text
$C,color_id,pos,size#
```

建议保留该协议用于后续色块避障，同时新增巡线协议：

```text
$L,error,angle,confidence,flags#
```

示例：

```text
$L,-23,5,86,1#
```

字段说明：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `error` | `int16_t` | 黑线中心相对画面中心的偏差，左负右正 |
| `angle` | `int16_t` | 路线方向趋势，左负右正 |
| `confidence` | `uint8_t` | 可信度，范围 0~100 |
| `flags` | `uint8_t` | 状态标志位 |

`flags` 建议定义：

| bit | 含义 |
| --- | --- |
| bit0 | `valid`，当前巡线结果有效 |
| bit1 | `lost`，当前丢线 |
| bit2 | `curve`，检测到明显弯道 |
| bit3 | `marker`，检测到色块或特殊标记 |

后续色块避障继续使用：

```text
$C,color_id,pos,size#
```

色块 ID：

| ID | 含义 |
| --- | --- |
| 0 | 无色块 |
| 1 | 红色 |
| 2 | 绿色 |
| 3 | 蓝色 |

## 6. K230D 脚本改造建议

当前文件：

```text
HARDWARE/K230/color_ecognition.py
```

建议保留现有 UART、摄像头、显示、色块识别函数，并新增巡线相关函数：

```python
find_line(img)
send_line(uart, line)
update_line_history(line)
```

建议的数据结构：

```python
line = {
    "error": 0,
    "angle": 0,
    "confidence": 0,
    "flags": 0,
}
```

主循环第一阶段建议流程：

```text
1. 获取图像
2. 识别黑线并计算 line
3. 发送 $L 巡线帧
4. 可选：继续识别色块，仅用于调试显示，不参与控制
5. 显示调试图像
```

第一阶段不建议让色块改变巡线结果。色块避障应在基础巡线稳定后再加入状态机。

## 7. STM32 端接入方案

### 7.1 新增视觉巡线模块

建议新增独立模块，不与旧八路传感器巡线模块混用：

```text
HARDWARE/VISION/
  vision_track.c
  vision_track.h
```

模块职责：

- 接收 UART 数据。
- 解析 `$L` 巡线帧。
- 保存最新视觉巡线状态。
- 提供 `error`、`angle`、`confidence`、`valid` 给控制层。
- 判断通信超时和丢线。

建议状态结构：

```c
typedef struct {
    int16_t error;
    int16_t angle;
    uint8_t confidence;
    uint8_t flags;
    uint8_t valid;
    uint8_t lost;
    uint32_t last_update_ms;
} VisionTrackData;
```

### 7.2 控制逻辑

STM32 控制不复用旧八路巡线判断表，直接使用视觉连续误差：

```text
turn_output = Kp * error + Kd * angle
```

然后叠加到左右电机：

```text
left_motor  = balance_output + speed_output - turn_output
right_motor = balance_output + speed_output + turn_output
```

实际正负号需要根据实车测试确认。如果车辆向错误方向修正，只需要反转 `turn_output` 符号或调整 K230D 输出方向。

### 7.3 丢线和通信异常处理

必须增加保护逻辑：

- 超过 100~200 ms 未收到有效 `$L` 帧，认为视觉数据超时。
- `valid = 0` 或 `confidence` 低于阈值，认为当前结果不可靠。
- 丢线时不要继续长期使用旧误差。

建议处理方式：

```text
短时间丢线：降低速度，短暂保持上一方向
持续丢线：停止前进，只保持平衡
恢复识别：平滑恢复巡线控制
```

## 8. 旧八路传感器代码关闭边界

旧巡线代码不删除，只注释或用宏关闭。建议关闭内容：

- `USER/main.c` 中旧巡线初始化调用。
- 主循环或定时任务中的旧巡线处理函数。
- 专用于八路传感器的 GPIO 采集逻辑。
- 旧巡线控制输出对电机转向的影响。

保留内容：

- 原 `HARDWARE/TRACKING/` 文件。
- 与电机、编码器、平衡控制、速度控制无关的公共代码。
- 已有串口、OLED、调试输出等基础功能。

建议使用编译宏区分：

```c
#define ENABLE_SENSOR_TRACKING 0
#define ENABLE_VISION_TRACKING 1
```

这样后续需要回退或对比测试时，可以快速切换。

## 9. 后续色块避障扩展

基础巡线稳定后，再加入色块避障。K230D 已经具备红、绿、蓝色块识别基础，可以继续使用：

```text
$C,color_id,pos,size#
```

建议后续流程：

```text
K230D 同时输出 $L 巡线帧和 $C 色块帧
STM32 平时根据 $L 巡线
检测到有效 $C 色块事件后进入避障状态机
避障动作完成后恢复视觉巡线
```

避障不建议直接写在 K230D 巡线算法里。K230D 只报告视觉事件，STM32 根据车体状态、电机控制和当前任务阶段决定如何避障。

## 10. 推荐实施步骤

1. 在 STM32 中关闭旧八路传感器巡线调用，不删除代码。
2. 在 K230D 脚本中新增 `find_line()` 和 `$L` 巡线帧发送。
3. STM32 新增视觉巡线串口解析模块。
4. 先用 K230D 发送固定 `$L` 测试数据，验证 STM32 解析正确。
5. 再接入真实图像处理，观察 `error`、`angle`、`confidence` 是否稳定。
6. 将视觉 `error` 和 `angle` 接入转向控制。
7. 低速实车调试 `Kp`、`Kd` 和速度。
8. 增加丢线保护。
9. 基础巡线稳定后，再加入色块避障状态机。

## 11. 当前阶段结论

当前阶段应把 K230D 作为新的视觉巡线传感器，重写一套基于图像连续误差的巡线逻辑。旧八路传感器巡线代码只保留作为历史参考和回退方案，不参与新视觉巡线控制。

第一阶段目标是让车辆在白底黑线地图上稳定跟随外侧大闭环，并正确过滤底部内圆、左侧短横线和色块干扰。等基础巡线稳定后，再把已有色块识别能力扩展为避障功能。
