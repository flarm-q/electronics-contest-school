# STM32 平衡小车工程分析报告

## 1. 工程概况

这是一个基于 `STM32F103C8` 的两轮自平衡小车工程，使用 STM32 标准外设库开发，Keil 工程文件为 `USER/UpStanding_Car.uvprojx`。

当前源码实际实现的核心能力如下：

- MPU6050 姿态采集与 DMP 解算
- 两路编码器测速
- 两路电机 PWM 驱动与方向控制
- 三环闭环控制：直立环 + 速度环 + 转向环
- USART2 八路巡线数据接入
- USART3 接收 K230 颜色识别结果
- OLED 实时显示姿态、巡线偏差、速度
- USART1 在线调参和调试打印

当前主流程中，超声波测距没有启用。

从控制对象上看，这个系统本质上是一个典型的“倒立摆”控制系统。小车需要通过持续调整左右轮的驱动力，让车体始终维持在平衡点附近。

### 结构上的关键结论

当前工程已经完成从“旧蓝牙/超声波演示结构”向“巡线 + K230 视觉输入结构”的迁移：

- `USER/main.c` 中已经没有超声波触发、回波和测距函数
- `PA2/PA3` 当前专用于 `USART2` 巡线通信
- `USART3` 当前职责是接收 K230 颜色识别结果，而不是旧蓝牙单字节遥控
- `HARDWARE/SENSOR/` 目录仍存在，但属于保留代码，不在当前主控制链路中

因此，阅读本工程时应以“当前主流程”而不是“历史残留目录”作为判断依据。

## 3. 系统启动与运行流程

`main()` 的初始化顺序如下：

1. `delay_init()`：初始化延时基准
2. `NVIC_Config()`：配置中断优先级
3. `uart1_init(9600)`：初始化 USART1，用于调试和在线调参
4. `uart3_init(9600)`：初始化 USART3，用于接收 K230 颜色识别结果
5. `Tracking_Usart2_Init(115200)`：初始化 USART2，用于八路巡线模块通信
6. `OLED_Init()`：初始化 OLED
7. `MPU_Init()` + `mpu_dmp_init()`：初始化 MPU6050 与 DMP
8. `MPU6050_EXTI_Init()`：配置 MPU6050 的外部中断输入
9. `Encoder_TIM2_Init()`：初始化左轮编码器
10. `Encoder_TIM4_Init()`：初始化右轮编码器
11. `Motor_Init()`：初始化电机方向引脚
12. `PWM_Init_TIM1(0, 7199)`：初始化 TIM1 PWM 输出
13. `OLED_ShowString()`：写入固定显示标签
14. `delay_ms(10000)`：等待姿态和巡线模块稳定
15. `Tracking_SendControlData(0,1)`：通知巡线模块开始发送数字量数据

之后进入 `while(1)`。主循环不承担核心控制计算，只负责低实时任务：

- `Tracking_ProcessRx()`：处理 USART2 接收 FIFO，拼帧并解析巡线数据
- `USART1_ProcessCommand()`：处理在线调参命令
- OLED 刷新显示
- 周期性打印调试信息

真正的平衡控制运行在 `EXTI9_5_IRQHandler()` 中断服务函数中。这个中断由 MPU6050 数据就绪信号触发。

这说明工程采用的是典型的前后台结构：

- 主循环负责显示、串口后台处理和调试
- USART2 中断只负责快速收字节
- USART3 中断只负责快速收 K230 数据帧
- MPU6050 外部中断负责高实时闭环控制

## 4. 当前主流程实现的功能

### 4.1 自平衡

通过 MPU6050 获取车体姿态角和角速度，通过编码器获取轮速，再通过三环控制输出左右电机 PWM，使车体维持直立。

### 4.2 前进 / 后退

当前代码中，前后目标速度主要有 3 个来源：

- K230 颜色帧预留：仅保留 `color_id / pos / size` 帧，不再接管 `Target_Speed`
- 八路巡线：通过 `Tracking_SetSpeed()` 写入固定巡线速度
- 历史兼容手动逻辑：保留 `Fore/Back` 变量作为兜底入口

需要注意的是，巡线模式下当前固定写入的是：

```c
#define TRACKING_SPEED -15
```

也就是说，在本工程当前的电机和编码器方向定义下，巡线前进对应的是负方向目标速度。

### 4.3 左转 / 右转

当前转向目标同样有 3 类来源：

- K230 颜色帧预留：仅保留位置帧，后续可接 LED 或状态灯
- 八路巡线：由 `Tracking_TurnPD(gyroz)` 直接给出转向输出
- 历史兼容手动逻辑：保留 `Left/Right` 作为兜底入口

### 4.4 八路巡线

八路巡线模块通过 `USART2` 与 STM32 通信，当前使用数字量协议。

主程序启动后会发送：

```c
Tracking_SendControlData(0,1);
```

表示请求巡线模块持续回传数字量数据。

接收到有效数据帧后：

- `tracking_active` 被置为 `1`
- `Tracking_IR_Data[0..7]` 保存八路状态
- 控制中断允许巡线逻辑接管高层速度/转向目标

当前巡线逻辑的特点是：

- 前进速度固定
- 转向由 `tracking_error` 连续映射得到
- 没有完整的丢线恢复状态机
- 没有专门的路口任务决策层

因此它更接近“连续纠偏巡线”，而不是“复杂赛道任务状态机”。

### 4.5 OLED 状态显示

当前 OLED 实时显示：

- `Pitch` 角度
- 巡线偏差 `Tracking_GetError()`
- 速度估算值 `((Encoder_Left + Encoder_Right) * 2.38)`

### 4.6 倾倒保护

当车体倾角超过安全阈值时，`Stop()` 会清零电机输出并置停机标志，防止电机持续暴力输出。

### 4.7 K230 颜色帧预留

当前工程已经把 `USART3` 接入 K230 颜色识别结果，协议格式为：

```text
$C,color_id,pos,size#
```

例如：

```text
$C,1,L,356#
```

含义：

- `color_id`：颜色编号
- `pos`：目标位置，`L=左`，`C=中`，`R=右`
- `size`：目标面积

当前这一路只保留帧传输，不再直接参与底盘控制。

STM32 在 `USART3_IRQHandler()` 中完成收帧与解析，在控制中断中按优先级决定是否接管高层速度和转向目标。

另外，`usart3.c` 还实现了超时保活机制：

- 每次收到合法帧，重装倒计时
- 每个控制周期递减一次
- 超时后自动清除旧视觉目标

这避免了“最后一帧结果永久生效”的风险。

### 4.8 超声波状态

当前源码主流程中：

- `USER/main.c` 已经没有超声波测距代码
- `PA2/PA3` 已让给 `USART2`
- `HARDWARE/SENSOR/` 仅作为保留目录存在

因此当前实际系统能力里，不应再把超声波测距算作“已启用功能”。

## 5. 控制架构与原理

### 5.1 控制总体思路

平衡车不能直接“命令站稳”，而是要通过控制轮子运动，让轮子始终追着重心跑。

当前工程采用经典三环控制：

- 直立环：负责“不倒”
- 速度环：负责“前后运动趋势”
- 转向环：负责“左右差速”

其中速度环的输出不是直接给电机 PWM，而是作为直立环的目标角补偿，这正是平衡车控制的核心思路。

### 5.2 直立环 PD

函数：

```c
int Vertical(float Med, float Angle, float gyro_Y)
{
    PWM_out = Vertical_Kp * (Angle - Med) + Vertical_Kd * gyro_Y;
    return PWM_out;
}
```

当前参数：

- `Vertical_Kp = -430`
- `Vertical_Kd = -1.92`

含义：

- `Angle - Med`：当前俯仰角相对机械中值的偏差
- `gyro_Y`：俯仰角速度

### 5.3 速度环 PI

函数核心：

```c
Encoder_Err = (encoder_left + encoder_right) - Target;
EnC_Err_Lowout = (1 - a) * Encoder_Err + a * EnC_Err_Lowout_last;
Encoder_S += EnC_Err_Lowout;
PWM_out = Velocity_Kp * EnC_Err_Lowout + Velocity_Ki * Encoder_S;
```

当前参数：

- `Velocity_Kp = -0.44`
- `Velocity_Ki = -0.0022`
- 低通滤波系数 `a = 0.7`

含义：

- 根据当前轮速和目标速度的偏差计算“前后倾趋势补偿”
- 通过积分消除长期速度偏差
- 输出给直立环作为目标角补偿量

### 5.4 转向环

函数：

```c
int Turn(int gyro_Z, int RC)
{
    PWM_out = Turn_Kd * gyro_Z + Turn_Kp * RC;
    return PWM_out;
}
```

当前参数：

- `Turn_Kp = 20`
- `Turn_Kd = 0.6`

说明：

- `RC` 表示高层给出的转向目标量
- `gyro_Z` 用于抑制偏航摆动
- 在巡线和 K230 接管时，`Turn_Kd` 会被动态调整

### 5.5 三环合成方式

在 `EXTI9_5_IRQHandler()` 中，控制链路大致为：

```c
Velocity_out = Velocity(Target_Speed, Encoder_Left, Encoder_Right);
Vertical_out = Vertical(Velocity_out + Med_Angle, Pitch, gyroy);

if(K230_AvoidanceActive())
{
    Turn_out = Turn(gyroz, Turn_Speed);
}
else if(Tracking_IsActive())
{
    Turn_out = Tracking_TurnPD(gyroz);
}
else
{
    Turn_out = Turn(gyroz, Turn_Speed);
}

MOTO1 = Vertical_out - Turn_out;
MOTO2 = Vertical_out + Turn_out;
```

可以看出：

- 速度环先输出目标倾角补偿
- 直立环产生基础驱动力
- 转向环在左右轮上做差分叠加

这是标准的差速式平衡车控制结构。

## 6. 中断驱动关系

### 6.1 控制中断源

`PB5` 被配置为 `EXTI_Line5`，由 MPU6050 数据就绪信号触发。

每次中断进入后，控制模块会依次完成：

1. 读取编码器速度
2. 读取姿态角和角速度
3. 更新 K230 视觉保活计数
4. 根据优先级选择高层行为来源
5. 运行三环控制
6. 输出左右电机 PWM
7. 执行倾倒保护

### 6.2 USART2 中断

`USART2_IRQHandler()` 当前只做一件事：

- 把收到的字节塞入 FIFO

真正的拼帧和协议解析放在主循环 `Tracking_ProcessRx()` 里完成。这样做的好处是：

- 缩短串口中断执行时间
- 减少对主控制链路的影响

### 6.3 USART3 中断

`USART3_IRQHandler()` 当前职责是解析 K230 颜色识别结果帧，而不是旧蓝牙遥控。

它使用简单状态机：

1. 遇到 `$` 认为一帧开始
2. 持续缓存后续字符
3. 遇到 `#` 认为一帧结束
4. 解析出 `color_id / pos / size`
5. 更新最新视觉结果和保活计数

历史保留的 `Fore / Back / Left / Right` 在收到视觉帧时会被清零，用于避免旧控制入口残留干扰。

### 6.4 编码器读取方式

TIM2 和 TIM4 都工作在编码器接口模式。

控制中断每次调用 `Read_Speed()` 后会立刻清零计数器，因此得到的是“一个控制周期内的增量速度”。

## 7. 高层行为优先级

当前工程的高层行为优先级已经明确变为：

1. K230 颜色帧预留
2. 八路巡线
3. 旧手动逻辑兜底

也就是说：

- 如果 K230 收到颜色帧，则仅保留结果供后续 LED 使用
- 如果没有有效视觉目标，但巡线模块已经工作，则进入巡线模式
- 只有前两者都不生效时，才回落到历史兼容的 `Fore/Back/Left/Right`

这意味着当前系统已经不是“蓝牙主控”的结构。

- 重新分配超声波 IO
- 放弃 USART2 巡线接入
- 或者更换为不冲突的外设方案

## 9. 各模块职责分析

### 9.1 `SYSTEM/usart`

作用：

- 初始化 USART1
- 打印调试信息
- 处理在线调参命令
- 查询和修改控制参数

### 9.2 `HARDWARE/CONTROL`

作用：

- 三环控制核心实现
- 高层行为优先级仲裁
- 电机输出合成
- 倾倒保护

这是整个工程最关键的模块。

### 9.3 `HARDWARE/TRACKING`

作用：

- 初始化 USART2
- 接收八路巡线模块数字量数据
- 计算 `tracking_error`
- 提供巡线模式下的转向控制

它当前实现的是“连续纠偏巡线”，不是完整赛道任务状态机。

### 9.4 `HARDWARE/USART3`

作用：

- 初始化 USART3
- 接收 K230 颜色识别结果
- 解析 `$C,color_id,pos,size#` 协议帧
- 提供视觉结果保活和超时清除机制

模块名虽然沿用了 `USART3`，但当前职责已经不是旧蓝牙输入。

### 9.5 `HARDWARE/ENCODER`

作用：

- 用 TIM2/TIM4 编码器模式读取左右轮速度

在控制层中，左轮速度被取反，目的是统一前进方向的符号定义。

### 9.6 `HARDWARE/MOTOR` 与 `HARDWARE/PWM`

作用：

- `MOTOR`：负责方向控制和停机
- `PWM`：负责占空比输出

两者组合形成完整电机驱动层。

### 9.7 `HARDWARE/SENSOR`

作用现状：

- 保留了旧超声波模块源码
- 当前主流程未启用
- 当前分析和维护不应把它视为“正在运行的功能模块”

## 11. 当前工程的优点

- 控制主链路比较清晰，前后台职责区分明确
- 三环控制结构合理，适合平衡车控制
- 姿态数据由外部中断驱动，实时性较好
- USART2 和 USART3 都采用了“中断收字节、主逻辑再处理”的思路
- K230 视觉结果有超时失效机制，控制更稳妥
- USART1 已支持在线调参，便于调试闭环参数

## 12. 当前工程存在的不足

### 12.1 文档和历史命名仍有阶段差异

当前源码已经进入“巡线 + K230 视觉输入”的阶段，但部分旧文档、旧命名仍保留“蓝牙”或“超声波主控”的历史描述。

例如：

- `README.md` 中对 `USART3` 的说明可能仍偏旧
- `HARDWARE/SENSOR/` 目录仍保留，但当前不参与主流程
- `Fore/Back/Left/Right` 变量仍保留，只是作为兼容兜底

### 12.2 巡线逻辑仍偏基础

当前巡线实现的重点是“连续纠偏”，还没有完整实现：

- 丢线恢复状态机
- 十字路口 / T 字路口识别
- 停车线识别
- 任务型动作切换

因此它更适合基础连续赛道，不等于完整比赛任务逻辑。

### 12.3 历史兼容入口仍然较多

为了减少改动，工程保留了旧手动逻辑变量和部分模块命名。这有利于兼容，但也会带来两个维护问题：

- 新接手的人容易误判当前真实主流程
- 后续继续扩展时，容易把历史兼容入口和当前业务入口混在一起

### 12.4 `HARDWARE/SENSOR` 处于保留状态

超声波模块目录仍在仓库中，但：

- 当前主流程未调用
- 当前 IO 已冲突
- 当前系统功能已经不依赖它

如果继续保留却不说明状态，容易给维护带来误导。

### 12.5 部分源码注释存在乱码

当前仓库部分 `.c/.h` 文件里的中文注释仍存在编码乱码。这不直接影响编译运行，但会影响阅读效率和后续维护。

## 13. 后续维护建议

1. 统一更新 `README.md`、工程说明和注释，明确当前主流程是“巡线 + K230”，不是“蓝牙 + 超声波”。
2. 若确认后续不再使用超声波，建议在文档中把 `HARDWARE/SENSOR` 明确标为历史保留模块。
3. 若后续需要恢复超声波，先解决 `PA2/PA3` 与 `USART2` 的资源冲突，再决定是否重新接入主流程。
4. 给巡线逻辑补充丢线恢复、路口识别和任务状态机。
5. 把高层行为仲裁逻辑抽成更明确的状态机，降低 `control.c` 中断函数的认知负担。
6. 统一整理源码注释编码，减少乱码。
7. 若继续扩展视觉能力，建议把颜色识别结果和避障策略进一步模块化，减少 `control.c` 中的策略硬编码。

## 14. 总结

这份工程当前的核心已经可以概括为一句话：

> 姿态中断驱动闭环控制，编码器提供速度反馈，USART2 提供巡线输入，USART3 提供 K230 视觉结果，OLED 和 USART1 负责调试与观察。

因此，当前工程不应再被理解为“蓝牙主控 + 超声波辅助”的结构，而应理解为：

- 底层是标准三环平衡车控制
- 中层是巡线和视觉输入接入
- 高层通过优先级仲裁决定当前行为来源

如果从学习价值看，这个工程非常适合理解以下问题：

- 平衡车三环控制是如何叠加的
- 为什么姿态采样通常放在中断里
- 巡线偏差如何映射成差速转向
- 视觉结果怎样通过高层目标接入原有平衡控制链路
- 嵌入式系统如何把高实时控制和低速后台任务分层组织
